## 背景：一筆掛號建立之後就沒有出口

目前一筆掛號提醒只有兩個結局：使用者手動刪除，或永遠留在清單裡。具體有四個缺口：

1. **過去的門診沒有任何刪除路徑。** 刪除鈕在編輯視窗的確認頁，而「過去的門診」區塊的卡片刻意不可點（避免長輩誤觸打開上次門診的表單），所以那些卡片點不到編輯，也就刪不掉。建錯的、重複建的舊紀錄會一直躺在那裡。
2. **「不去了」只能用刪除。** 醫院改期、病人臨時不去、掛錯時段——這些情況使用者唯一能做的是刪除，連「我本來有這個門診、後來取消了」的紀錄都一起消失。後端資料模型有 `cancelled` 狀態，但**沒有任何路徑會寫入**（見後端實作報告 §8）。
3. **未到診之後沒有下一步。** 後端在當日結束把沒回報到診的標成 `missed`，然後就停在那裡。使用者看到一張「未到診」的卡片，沒有任何動作可做——而現實中真正要做的事是「改約」。
4. **清單無上限地長大。** 前端改成連過去的門診一起抓（要做「再掛一次」與「常去的醫院」），但後端的 `GET /reminders?include_past=true` 沒有分頁。長輩看幾年下來，每次打開頁面都要把所有歷史撈回來。

這份文件設計這四件事的使用者流程，並列出前後端的代辦。

## 設計原則

- **「取消」與「刪除」是兩件事，介面上要分得開。**「這次門診不去了」是事實，該留下紀錄；「這筆我建錯了」才是刪除。
- **不新增狀態、不新增欄位就能解決的，就不要新增。** 例如「未到診要不要提醒使用者處理」，用「門診結束後 7 天內置頂」就能解決，不必做一個「已讀」欄位。
- **危險的動作不放在卡片上，而且要說清楚後果。** 長輩誤觸的成本很高：取消、刪除、刪除全部都要先經過一層，確認框要寫出「會刪掉幾筆」「什麼不受影響」。
- **清單只載入使用者真的會看的量。** 其餘的用「載入更多」。

## 流程一：不去了（取消這次門診）

### 進入點

編輯視窗**確認頁內容的最下方**（以分隔線隔開），兩顆分開、整列寬的按鈕。不放在對話框底部的按鈕列：那裡只留「上一步」「儲存」，大字級下不會擠成好幾行，刪除也不會貼著儲存（2026-09-12 拍板）。

| 按鈕 | 樣式 | 意思 | 結果 |
|---|---|---|---|
| 取消這次門診 | outline，一般大小 | 這次不去了 | `status = cancelled`，停止所有推播，紀錄移入「過去的門診」並標示「已取消」 |
| 刪除這筆紀錄 | destructive | 這筆建錯了 | 整筆消失，無法復原 |

目前那裡只有「刪除此提醒」。改成兩顆，並把刪除的文案改成「刪除這筆紀錄」——「提醒」聽起來像是只關掉通知，但它其實會把整筆資料刪掉。

**卡片上不放取消。** 卡片上只有「我已出發」「我已到診」，那兩顆是門診當天要用的；取消是低頻、且後果明確的動作，值得多按一步。

### 確認框文案（zh-TW）

- 標題：取消這次門診
- 內文：取消後，你和家人都不會再收到這次門診的提醒。這筆紀錄會留在「過去的門診」裡，之後可以「再掛一次」。
- 動作：取消這次門診 ／ 返回

### 已取消之後

- 立刻從「即將到來」移到「過去的門診」，狀態徽章顯示「已取消」（灰色＋禁止圖示，已經有樣式）。**不論門診日期**：一筆下個月的門診取消了，也歸在「過去的門診」，不留在即將到來的清單裡。
- 取消已經取消過的：200 冪等，不回錯誤（兩位家屬各按一次是常態，比照「我已出發／到診」）。
- 已取消的不能再改門診時間；要改期就「再掛一次」，舊的那筆留著當作「這次後來取消了」的紀錄。
- 仍然可以「再掛一次」——改期是最常見的後續。
- 已取消的不列入「常去的醫院」的統計（那一次並沒有去，現有邏輯已經這樣做）。

### 誰可以取消、要不要通知

- 權限與 `depart`／`attend` 相同：本人，或對就診者有 `GENERAL WRITE` 的家屬（GUARDIAN、CAREGIVER）。只有讀取權的 MEMBER 不行，影子模式下也一樣（已拍板）。
- **已拍板：不因為取消而發任何推播**，本人取消不通知家屬，家屬代為取消也不另外通知本人。取消本來就會讓後續三則提醒都不再發出，家屬自然會發現；為了一次取消再多發一則推播，只是增加打擾。

## 流程二：沒去（未到診的後續）

### 「需要處理」區塊

門診結束後，後端把狀態標成 `missed`。此時在清單**最上方**出現一個區塊：

```
需要處理
┌─────────────────────────────────────┐
│ 未到診                               │
│ 9/15（週二）09:30                    │
│ 臺大醫院 · 心臟內科                   │
│                                      │
│ [ 改約 ]            [ 刪除這筆紀錄 ] │
└─────────────────────────────────────┘
```

- **只在門診結束後 7 天內顯示**（已拍板），之後自動沉到「過去的門診」。不需要「知道了」按鈕，也不需要後端記「使用者已讀」——沒人處理的話它會自己消失，不會變成另一個永遠掛在那裡的東西。
- 「改約」＝現有的「再掛一次」，帶入醫院、科別、醫師，從第二步開始。
- 這個區塊同時解決「未到診沒有下一步」與「使用者需要一個地方刪掉它」。

以下三條 2026-09-12 拍板：

- **改約過的就不再列出。** 同一家醫院的同一科，已經有一筆比它晚、而且沒有取消的掛號，就當作處理過了。不論那一筆是按「改約」建的還是另外新增的都算，不需要新增欄位。不這樣做的話，長輩改約完回到清單，那張「未到診」還掛在最上面好幾天，會以為沒成功而再掛一次。
- **7 天內也同時出現在「過去的門診」。** 後端 `scope=past` 的 `total_count` 與「刪除全部歷史紀錄」都會算進它；從過去的門診拿掉，畫面上的筆數就會跟確認框的筆數對不上。過去的門診預設收起，平常看不到重複。
- **只有寫入權的人看得到這個區塊。** 只有讀取權的家人一顆按鈕都沒有，標題卻寫著「需要處理」。那些紀錄照樣在過去的門診裡看得到。
- 7 天以門診自己的日期算：9/15 的門診從 9/16 顯示到 9/22，9/23 起只留在過去的門診。
- 上方出現「需要處理」時，即將到來的清單加上「即將到來的門診」標題，分得出哪些要處理。

### 不做「我其實有去，補登到診」

已拍板不做。補登的到診時間不可信（隔三天才按的「我到了」不是紀錄，是猜測），而且要為此放寬後端「門診當天才能回報」的防呆。未到診的紀錄就維持未到診；使用者真正需要的下一步是改約，那個有做。

## 流程三：清掉過去的紀錄

### 單筆刪除：每張過去的卡片都要有

「過去的門診」的卡片維持不可點（避免誤觸），但右側動作區從一顆變兩顆：

```
[ 再掛一次 ]  [ 刪除 ]
```

「刪除」用 destructive 樣式的**文字＋圖示**按鈕（不是純圖示：垃圾桶對長輩不夠明確），`aria-label` 仍寫完整：「刪除 8/25（週二） 臺大醫院 心臟內科 的紀錄」。按下後經過確認框，確認框裡要寫出是哪一次門診——清單裡好幾張卡長得很像。

### 刪除全部歷史紀錄

放在「過去的門診」區塊展開後的**最下方**，不是最上面：要先捲過自己的紀錄才會看到它，這一段距離本身就是一道防線。

**只有本人看得到這顆按鈕**（已拍板）：檢視家人的掛號時不顯示。家屬（含 GUARDIAN）一律不能一次刪光長輩的紀錄；單筆刪除仍然可以代勞。

- 樣式：destructive outline，整列寬
- 文字：刪除全部歷史紀錄（{{count}} 筆）

**確認框文案（zh-TW）**

- 標題：刪除全部歷史紀錄
- 內文：這會刪掉「過去的門診」裡全部 {{count}} 筆紀錄，包含已到診、未到診與已取消的。刪除後無法復原，也不能再用它們「再掛一次」。
- 補充一行：即將到來的門診不受影響。刪除後，「常去的醫院」只會剩下即將到來的門診用到的醫院。
  （原本寫「也會跟著清空」，但還有即將到來的門診時，那幾家醫院仍會列在常去的醫院裡，所以改成照實說。）
- 動作：刪除全部 {{count}} 筆 ／ 返回

主要動作的文字刻意帶上筆數（「刪除全部 23 筆」），讓使用者在按下去的那一刻再看到一次規模。

**範圍**：只刪「過去的門診」，即將到來的一筆都不動。這是這顆按鈕能夠存在的前提——它刪掉的是歷史，不是正在等待的提醒。

**「常去的醫院」會跟著變少**：那份清單是從紀錄統計出來的，刪光過去的紀錄之後只剩即將到來的門診用到的醫院，下次新增多半得重新搜尋醫院。這是真實的代價，所以寫在確認框裡，不能讓使用者事後才發現。

**必須由後端一次刪完**，不是前端逐筆呼叫 `DELETE`：前端只握有目前載入的那幾筆（分頁之後更是如此），逐筆刪會刪不乾淨，中途失敗還會留下刪一半的狀態。

## 流程四：清單不再無上限地長大

### 前端

- 「過去的門診」預設只顯示最近 **20 筆**（目前是 10 筆，但那只是顯示上限，資料還是全抓）。
- 區塊底部加「載入更多」，一次再拿 20 筆。
- 「常去的醫院」只統計即將到來的門診與**最近 20 筆**過去的門診（過去的第一頁），不為它另外去抓更早的紀錄（2026-09-12 拍板，取代原本的「最近 12 個月」：分頁之後前端手上只有第一頁，保證不了 12 個月；最近 20 次門診已經足以代表常去哪幾家）。

### 後端

`GET /api/appointments/reminders` 改成依 `scope` 分兩種查詢（細節見後端需求文件）：

- `scope=upcoming`：未取消、而且當日還沒結束的門診，由早到晚，不分頁（量本來就少）
- `scope=past`：當日已結束**或已取消**的門診，由新到舊，`limit` + `cursor` 分頁，回應附 `total_count`

「過去」的定義只在後端存在一處，列表與「刪除全部歷史紀錄」共用同一條界線：畫面上「過去的門診」裡看到幾筆，按下刪除全部就刪那幾筆。

原本寫的「`include_past=true` 預設只回最近 12 個月」拿掉：已拍板永久保留，「載入更多」必須能一路翻到最舊的紀錄；效能由分頁處理就夠了。

### 保留期：永久保留（已拍板）

不做自動刪除。掛號紀錄是就醫史的一部分，長輩回診時「上次是什麼時候去的」有實際用途；一筆紀錄只有幾百個位元組，效能用分頁解決就夠。自動刪除還有一個問題：必須事先告知使用者，否則等於未經同意毀掉他的資料。

**要清除資料時由使用者自己決定**，兩個入口都在上面的「流程三」：單筆刪除、刪除全部歷史紀錄。

## 狀態機（更新後）

```
                    ┌──── 取消這次門診 ────┐
                    │                      ▼
scheduled ──depart──▶ departed ──attend──▶ attended
    │                     │                 (終局)
    │                     │
    └───────attend────────┘
    │
    └──── 取消這次門診 ────▶ cancelled（終局，可再掛一次）

scheduled／departed ──（當日結束）──▶ missed（終局，可改約）
                                        │
                                        ├─ 7 天內：顯示在「需要處理」
                                        └─ 之後：沉入「過去的門診」

任何狀態 ──刪除這筆紀錄──▶ （整筆消失）
過去的門診 ──刪除全部歷史紀錄──▶ （整批消失，即將到來的不受影響）
```

`cancelled` 從「資料模型有但寫不進去」變成真的會用到的狀態。

## 後端需求

1. **`POST /api/appointments/reminders/{id}/cancel`**
   - 權限與 `depart`／`attend` 相同（本人或 `GENERAL WRITE` 的家屬）
   - 從 `scheduled`／`departed` 可以取消；`attended`／`missed` 回 409；已經是 `cancelled` 回 200 冪等
   - 已取消的掛號 `PUT` 改門診時間回 409（變更既有行為：目前會重置回 `scheduled`）
   - 寫入 `cancelled_at`、`cancelled_by_user_id`（與出發／到診同一個慣例）
   - 取消所有尚未發出的推播
   - **不發任何推播通知**（已拍板）
2. **一次刪除全部歷史紀錄的端點**，例如 `DELETE /api/appointments/reminders?target_user_id=&scope=past`
   - 只刪 `scope=past` 的那些（當日已結束或已取消），與列表用同一份判定；即將到來的一筆都不能動
   - 回傳實際刪除的筆數，讓前端顯示「已刪除 N 筆」
   - **只有本人**；帶了別人的 `target_user_id` 回 403，不退回去刪操作者自己的
3. **`GET /reminders` 依 `scope` 分查詢**：`upcoming` 不分頁；`past`（當日已結束或已取消）由新到舊、`limit` + `cursor` 分頁、附 `total_count`；不設 12 個月的預設上限；不帶 `scope` 時維持現有行為
4. **不做保留期排程**（已拍板永久保留）

## 已拍板的決策（不需要再問）

- 取消門診**不發任何推播**，本人與家屬都不通知
- 「需要處理」停留 **7 天**
- **不做**「我其實有去，補登到診」
- 掛號紀錄**永久保留**，不做自動刪除；清除資料由使用者自己按「刪除這筆紀錄」或「刪除全部歷史紀錄」
- **只有讀取權的家人（MEMBER）不能更動掛號**，影子模式下也一樣；家屬推播也只送給 GUARDIAN、CAREGIVER
- **「刪除全部歷史紀錄」只有本人可以按**，家屬（含 GUARDIAN）一律不行
- 「需要處理」：**改約過的不再列出**（同醫院同科已有更晚、未取消的掛號）；7 天內**同時**出現在過去的門診；**只給有寫入權的人**看
- 「取消這次門診」「刪除這筆紀錄」放在**確認頁內容的最下方**，不放在底部按鈕列
- 「常去的醫院」只統計即將到來的門診與**最近 20 筆**過去的門診，不做 12 個月的判斷
- **已到診之後只能改備註**，醫院、科別、門診時間、醫師、看診號、推播開關都不能改（前端不給入口；後端只擋改時間）。到診是終局，改院所等於改寫紀錄；而且當天可改、移到過去的門診後不能改，規則前後不一致
- 已到診的門診留在「即將到來」直到當日結束，不會一按到診就移到過去的門診：當天打開就看得到「幾點由誰回報到診」，家屬確認最直接
